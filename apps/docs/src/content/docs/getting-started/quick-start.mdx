A `Path` is an immutable, normalised path string. Every operation returns a new
`Path`; nothing mutates.

```ts
import { FileSystem, Path, json } from "@archont561/pathway";

const root = Path.cwd();

// Normalisation happens once, on construction.
root.value; // "/home/you/project"
new Path("/a/b").value === new Path("/a/./c/../b").value; // true

// join normalises as it goes, and takes any number of segments.
root.join("src", "../lib", "index.ts").value; // "/home/you/project/lib/index.ts"

// Path components, pathlib's names.
const p = new Path("/a/b/file.tar.gz");
p.parent.value; // "/a/b"
p.name; // "file.tar.gz"
p.stem; // "file.tar"
p.ext; // ".gz"

`${p}`; // "/a/b/file.tar.gz" — toString()
```

String operations are handled in TypeScript by [`pathe`], so they work on
Windows and POSIX without a platform check and never cross the FFI boundary.

## Typed JSON I/O

The built-in JSON serializer is generic at the `Path` seam:

```ts
interface Config {
  name: string;
  enabled: boolean;
}

const configPath = root.join("config.json");
const config: Config = { name: "pathway", enabled: true };

await configPath.write(json, config, { atomic: true, fsync: true });
const loaded = await configPath.read<Config>(json);
```

A plain `Path` has JSON registered for `.json`, so automatic resolution is also
available:

```ts
const loaded = await configPath.read(); // unknown when no serializer is passed
```

Malformed data is reported by the serializer rather than silently returned.
The serializer works on bytes, so custom codecs can choose their own text or
binary representation:

```ts
import type { Serializer } from "@archont561/pathway";

const tagged: Serializer<string> = {
  name: "tagged",
  native: false,
  extensions: [".cfg"],
  parse: (bytes) => new TextDecoder().decode(bytes).replace(/^value:/, ""),
  stringify: (value) => new TextEncoder().encode(`value:${value}`)
};
```

## Per-filesystem registries

Serializer mappings belong to a `FileSystem` instance. They are not global:

```ts
const appFs = FileSystem.create({ serializers: [json, tagged] });
const testFs = FileSystem.create({ serializers: [json] });

await appFs.path("settings.cfg").write(tagged, "production");
const value = await appFs.path("settings.cfg").read();

// The test filesystem does not inherit the .cfg mapping.
await testFs.path("settings.cfg").read(); // rejects: no serializer for .cfg
```

A mapping can also be registered explicitly:

```ts
appFs.register(tagged, ["data"]);
const data = await appFs.path("settings.data").read();
```

## Atomic writes

`atomic: true` writes to a collision-safe temporary file beside the target and
renames it into place. `fsync: true` also flushes the temporary file and best
-effort flushes the containing directory.

```ts
await root.join("config.json").write(
  json,
  { name: "pathway", enabled: true },
  { atomic: true, fsync: true }
);
```

## Native walk

Walking is the operation that uses the native addon. It yields batches rather
than crossing the N-API boundary once per entry:

```ts
import { walkFiles } from "@archont561/pathway";

for await (const batch of walkFiles(root.value, {
  glob: ["**/*.ts"],
  exclude: ["node_modules", "dist"],
  hash: "blake3"
})) {
  for (const entry of batch) {
    console.log(entry.value, entry.hash);
  }
}
```

Build the addon before consuming a walk:

```bash
pixi run build-native
```
