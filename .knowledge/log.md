* **CI — turbo's task cache is now restored between runs**: `ci.yml` cached the pixi environment and `target/` but never `.turbo`, so every run re-executed the entire turbo graph — the debug addon, the TypeScript build, the Astro production build and `astro check` — even on byte-identical inputs; `Swatinem/rust-cache` only made the cargo half finish faster, it did not stop turbo running the task. An `actions/cache@v6.1.0` step on **`.turbo/cache`** was added to `ci.yml` and to `docs.yml` (whose two steps are also turbo tasks now), sharing one key prefix so a docs-only pull request can reuse the Astro build `ci` already produced. Three details that are easy to get wrong and were checked rather than assumed: the path is `.turbo/cache` and not turbo 1.x's `node_modules/.cache/turbo` (which would restore nothing and never error); the `restore-keys` prefixes are what produce hits, since a key on `github.sha` alone can never hit; and correctness does not depend on the key at all, because turbo rehashes every declared input against whatever was restored — confirmed by editing `pixi.lock` and watching all nine task nodes invalidate. The remote-cache option was declined: it would put a service and a token in front of a build that `.pixi-sandbox.toml` requires to work offline. Local wall-clock gains are real; the CI before/after numbers still need a pull request, because `ci.yml` does not trigger on pushes to topic branches.
