# Knowledge Base Update Log

## 2026-09-30
* **Orchestration — one verb, one path (pixi ⇄ turbo)**: pixi and turbo were both orchestrating and disagreeing. Six pixi tasks used `cwd = "<package>"` and ran a package script with turbo nowhere in the chain, so they neither read nor wrote the cache and silently diverged from the turbo task for the same verb — most visibly `pixi run ci`, which built the Astro site **twice** (once via `turbo run build`, once via `docs-build` going around it) for byte-identical output. Fixed by making the root `package.json` the single turbo entry point (`docs:build`/`docs:check`/`docs:dev`/`docs:preview`/`build:native*` are `turbo run <task> --filter=<pkg>`) and reducing every pixi task to `bun run <script>`; the rule *"a pixi task may never use `cwd = "<a workspace package>"`"* is now written into `pixi.toml` and [AGENTS.md](../AGENTS.md). Three real defects fell out: **(1)** `test` only depended on `^build`, which for `packages/path` resolved to `@repo/typescript-config` (no build script) — so `turbo run test` never built the `.node` addon, a hole backlog task-3 would have hit as a flaky test; it now depends on `build:native`. **(2)** `PATHWAY_VERSION` was redundant (it resolved from the same `[workspace.package] version` the site already reads directly) while making builds hash differently depending on whether it was set; removed from `globalEnv`, the pixi tasks and `apps/docs/src/version.ts`, and replaced with a Package Configuration (`apps/docs/turbo.json`) that declares the root `Cargo.toml` and `scripts/version.ts` as build inputs — otherwise a version bump would serve a cached site quoting the old number. **(3)** `benches/*` was a phantom: the glob matched nothing, `bun.lock` had zero references, yet a turbo `bench` task, a pixi `bench` task, a biome override and a lefthook glob all pointed at it, so `pixi run bench` exited 0 having run nothing — all five references removed until backlog task-4 lands. Also: `apps/docs` renamed `check` → `typecheck` so the repo-wide `typecheck` (and therefore `gates`) finally covers the site; root script `lint` → `lint:js` to end the collision with the pixi `lint` aggregator; `packageManager` dropped from `packages/path` (root-only — it describes the repo, not the tarball). Updated: [repo-structure.md](/implementation/repo-structure.md).
* **Docs — `repo-structure.md` aligned with the actual workspace**: the structure doc still described the pre-scaffold layout — a `pnpm-workspace.yaml`/root `tsconfig.base.json` tree (one stale line had silently survived an earlier edit), a pnpm+vitest `package.json` sketch, and "pnpm is the standard" decision rows. Rewritten to the real state: bun workspaces declared in the root `package.json` (no workspace yaml, one `bun.lock`), `@repo/typescript-config` as the shared-tsconfig home, the actual `@archont561/pathway` manifest (`napi.binaryName` = `pathway`, `build:native` debug/release scripts, `@repo/typescript-config` as a `workspace:*` devDep), `.cargo/config.toml` as a gitignored file written by `pixi-sandbox restore`, and the platform `optionalDependencies` matrix noted as release-pipeline-generated (`napi publish`), never hand-maintained. One matching pnpm mention fixed in [phase-plan.md](/implementation/phase-plan.md) (Step 1.1).
* **Structure — `@repo/typescript-config` internal package**: the shared TS config moved from a root `tsconfig.base.json` into a workspace package (`packages/typescript-config`, `@repo/*` = internal-by-convention, never published) with a faithful split: `base.json` is the language+resolution contract for any package, `library.json` adds the declaration emit a publishable package wants (benches, when they arrive, extend `base.json` only). Consumers reach it through a real dependency edge (`workspace:*`), turbo drops `tsconfig.base.json` from `globalDependencies` (a config change now invalidates only the `build`/`typecheck` tasks of consuming packages, via explicit `$TURBO_ROOT$/packages/typescript-config/**` inputs, instead of every task) — the turbo-bundled docs' "no root tsconfig" guidance. Version handling stays at the root on purpose: `[workspace.package] version` in Cargo.toml remains the single source; the npm/biome/convco root config is the repo-wide config surface. Updated: [repo-structure.md](/implementation/repo-structure.md).
* **Decision — public names (Step 0 sign-off, partial)**: npm **`@archont561/pathway`** (the scope is lowercase because npm rejects uppercase in package names; unscoped `pathway` on npm is taken) and crates.io **`pathway-fs`** (ergonomic Rust surface) + **`pathway-fs-core`** (engine core) + `pathway-fs-engine` (NAPI glue, `publish = false` forever) — `pathway` on crates.io is squatted by a 2022 placeholder (v0.0.0), hence the `-fs` family; the crates.io *reservation* is still outstanding. Renamed everywhere from the `myorg-*` placeholders; crates stay `publish = false` until reserved. Also: the addon binary is `pathway.<platform>.node` via `napi.binaryName` in the package manifest, and `napi build` is wired into turbo (`build:native` task, debug default + release variant) and pixi (`pixi run build-native`). The hand-written loader's platform-suffix logic was wrong (rust triple vs NAPI-RS npm spelling) and now computes `linux-x64-gnu` / `darwin-arm64` / `win32-x64-msvc` correctly. Updated: [phase-plan.md](/implementation/phase-plan.md) (Step 0 items checked off), plus name references across the bundle.
