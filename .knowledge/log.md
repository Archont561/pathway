# Knowledge Base Update Log

## 2026-09-30
* **Orchestration — one verb, one path (pixi ⇄ turbo)**: pixi and turbo were both orchestrating and disagreeing. Six pixi tasks used `cwd = "<package>"` and ran a package script with turbo nowhere in the chain, so they neither read nor wrote the cache and silently diverged from the turbo task for the same verb — most visibly `pixi run ci`, which built the Astro site **twice** (once via `turbo run build`, once via `docs-build` going around it) for byte-identical output. Fixed by making the root `package.json` the single turbo entry point (`docs:build`/`docs:check`/`docs:dev`/`docs:preview`/`build:native*` are `turbo run <task> --filter=<pkg>`) and reducing every pixi task to `bun run <script>`; the rule *"a pixi task may never use `cwd = "<a workspace package>"`"* is now written into `pixi.toml` and [AGENTS.md](../AGENTS.md). Three real defects fell out: **(1)** `test` only depended on `^build`, which for `packages/path` resolved to `@repo/typescript-config` (no build script) — so `turbo run test` never built the `.node` addon, a hole backlog task-3 would have hit as a flaky test; it now depends on `build:native`. **(2)** `PATHWAY_VERSION` was redundant (it resolved from the same `[workspace.package] version` the site already reads directly) while making builds hash differently depending on whether it was set; removed from `globalEnv`, the pixi tasks and `apps/docs/src/version.ts`, and replaced with a Package Configuration (`apps/docs/turbo.json`) declaring the root `Cargo.toml` and `scripts/version.ts` as the docs build's inputs. **Correction, measured after the fact:** the first write-up of this claimed the site would otherwise serve a stale cached version. It would not have — the root `build` task depends on `build:native`, and a package with no `build:native` script still receives a phantom one in the graph whose inputs are the entire Rust workspace, so the bump was caught by accident while *every* `crates/**` edit also rebuilt the site. The Package Configuration's real value is replacing that accident with the declared edge: `Cargo.toml` + `scripts/version.ts` in, `crates/**` out (verified by hash comparison — a `crates/core/src/lib.rs` edit changes the docs hash without it and leaves it untouched with it). **(3)** `benches/*` was a phantom: the glob matched nothing, `bun.lock` had zero references, yet a turbo `bench` task, a pixi `bench` task, a biome override and a lefthook glob all pointed at it, so `pixi run bench` exited 0 having run nothing — all five references removed until backlog task-4 lands. Also: `apps/docs` renamed `check` → `typecheck` so the repo-wide `typecheck` (and therefore `gates`) finally covers the site; root script `lint` → `lint:js` to end the collision with the pixi `lint` aggregator; `packageManager` dropped from `packages/path` (root-only — it describes the repo, not the tarball). Updated: [repo-structure.md](/implementation/repo-structure.md).
* **Orchestration — the refactor verified on a real toolchain, and the airlock proved out**: the entry above was written and statically checked in a sandbox with no `pixi`, `bun` or `cargo`, so none of it had been executed. It has now been run end to end. The toolchain came from this repository's own offline transport branch `sandbox/developer-linux-64` — there is no network path from that sandbox to rustup, crates.io or conda-forge, so this is also the first end-to-end proof that the `pixi-sandbox` airlock does what it was designed for: `pixi.lock` at HEAD hashes to exactly the `lock_sha256` in the transport manifest, `pixi install --frozen --offline` is a 68 ms no-op, and `cargo build --offline --workspace` compiles all three crates from the vendored registry in 37 s. Results: **`pixi run gates` and `pixi run ci` both exit 0**; the Astro production build now runs **exactly once** under `ci` (it ran twice before); and on a cold cache with no `.node` present, `pixi run test` builds the addon *before* `bun test` — the regression the refactor exists to prevent, previously argued from a dry run and now observed. `pixi run build-native` and `turbo run build:native` land on the same hash (`5a5d7aaa…`, miss then hit), as do `pixi run docs-build` and `pixi run build` for `pathway-docs` (`75407e8d…`), so no pixi task bypasses the cache any more. The invalidation matrix behaves as designed, by hash: a `crates/**` edit invalidates `build:native`/`build`/`test` and leaves `pathway-docs#build` **untouched**; a `packages/path/src/**` edit invalidates `build`/`test` but **not** `build:native`; an `.mdx` edit moves only the docs tasks; a version bump moves the docs hash and the rebuilt site quotes the new number. `astro check` costs ~6.3 s of a 15.9 s cold `gates` (5.8 s warm), which is cheap enough that it stays in the gate — no `gates-fast` split. Two things the refactor had missed also surfaced: `.github/workflows/docs.yml` still documented `PATHWAY_VERSION` as live behaviour (the only such claim left in the repo — corrected), and **`test-doc-rs` is a vacuous gate**: `cargo test --doc` reports `0 passed; 0 failed` for both crates because the workspace contains no doctests at all, so a gate justified on "a public Rust API is only as documented as its examples compile" cannot currently fail (backlog task-8). Rust coverage is 75.68% region / 80.00% line, with `core/src/fs/atomic.rs` and `engine/src/lib.rs` at zero.
* **CI — turbo's task cache is now restored between runs**: `ci.yml` cached the pixi environment and `target/` but never `.turbo`, so every run re-executed the entire turbo graph — the debug addon, the TypeScript build, the Astro production build and `astro check` — even on byte-identical inputs; `Swatinem/rust-cache` only made the cargo half finish faster, it did not stop turbo running the task. An `actions/cache@v6.1.0` step on **`.turbo/cache`** was added to `ci.yml` and to `docs.yml` (whose two steps are also turbo tasks now), sharing one key prefix so a docs-only pull request can reuse the Astro build `ci` already produced. Three details that are easy to get wrong and were checked rather than assumed: the path is `.turbo/cache` and not turbo 1.x's `node_modules/.cache/turbo` (which would restore nothing and never error); the `restore-keys` prefixes are what produce hits, since a key on `github.sha` alone can never hit; and correctness does not depend on the key at all, because turbo rehashes every declared input against whatever was restored — confirmed by editing `pixi.lock` and watching all nine task nodes invalidate. The remote-cache option was declined: it would put a service and a token in front of a build that `.pixi-sandbox.toml` requires to work offline. Local wall-clock gains are real; the CI before/after numbers still need a pull request, because `ci.yml` does not trigger on pushes to topic branches.
* **Orchestration — pixi.toml reduced to repo-wide verbs, every package-scoped command delegated**: `pixi.toml` carried 41 tasks, most of which were a package's command written out in the root manifest — `clippy`, `test-rs`, `fmt-check-rs`, `deny`, `build-rs`, `coverage`, `build-native`, `docs-build`, `docs-check`, `docs-dev`, `docs-preview`, `lint-js`, `fix-js`, `lint-actions`. It is now **25**, and contains no cargo, tsc, astro or biome invocation at all. Two kinds of task remain: repo-wide verbs (`build`, `build-release`, `test`, `typecheck`, `lint`, `fmt`, `coverage`, `dev`), each one line of `bun run <verb>` into turbo; and repo management (changelog, backlog, sandbox transport, hooks) plus the two checks nothing in the workspace can own (`lint-advisories` needs the network, `lint-sandbox-plan` needs a release binary). `gates` is now three verbs instead of nine tasks, because a verb spans both languages: `lint` is rustfmt + clippy + cargo-deny + biome + actionlint, `test` is `cargo nextest` + the Rust doctests + the Bun suites, `typecheck` is `tsc --noEmit` + `astro check`. Adding a check means adding a script to the package that owns it, not a line here. The commands moved into **`crates/package.json`** (every cargo command), `packages/path` (the addon) and `apps/docs` (the site); the escape hatch is a filter on the same graph — `turbo run lint --filter=@repo/rust`, `bun run docs:dev` — never a re-added task. **This resolves backlog task-7 as adopted**, by a route that task had ruled out and a route it had not considered: the Cargo workspace is **one** turbo package (`@repo/rust`), not three. Cargo's unit of work is the workspace — it holds a single lock on `target/` — so per-crate packages serialise on it: measured, three parallel `cargo clippy -p …` took 320-365 ms against 195 ms for one `--workspace` run, logging `Blocking waiting for file lock on build directory`. One package also declares no dependencies, so the Cargo graph is not restated anywhere, which was task-7's stated prohibition; and deleting the granular pixi tasks rather than keeping them beside a bundle answers its "two spellings" objection — each flag is now written exactly once. The payoff was much larger than task-7 assumed, because the old pixi tasks bypassed the cache entirely and re-ran on every commit: **warm `pixi run gates` went from 5,781 ms to 794 ms (7x)**, a README-only edit is now a cache hit on the Rust gate (757 ms), and an edit under `crates/` still misses and re-runs. One nuance worth keeping: `crates/turbo.json` marks `build:release` `cache: false`, because its output is `$TURBO_ROOT$/target` — outside the package, so turbo cannot restore it and a hit would skip a build whose artefacts may be gone. `lint`, `test` and `coverage` are cached, their only output being "it passed" plus `lcov.info`, which now lands at `crates/lcov.info`.
* **CI — one command, three caches, and docs gated on green**: `ci.yml` was fifteen `pixi run <task>` steps; it is now three caches (the pixi environment, `target/` via rust-cache, `.turbo/cache`) and **`pixi run ci`**, plus the two steps that cannot run offline and the codecov upload (now reading `crates/lcov.info`). The thing CI runs is the thing a laptop runs, by construction. `docs.yml` no longer duplicates any of it: it used to rebuild and re-check the site on every docs-touching push, racing the workflow that validates it, even though `pixi run ci` already builds and type-checks `apps/docs` as part of the turbo graph. It now triggers on `workflow_run` of `ci`, runs only when `github.event.workflow_run.conclusion == 'success'`, and checks out `workflow_run.head_sha` so what publishes is exactly the tree that went green rather than whatever main has drifted to. Its build step is `bun run docs:build` — the filtered turbo entry point, since pixi no longer exposes a docs task — and it shares ci's turbo cache key, so the Astro build ci already produced is restored rather than repeated.
